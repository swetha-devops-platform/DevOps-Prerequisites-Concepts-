There are Concepts in Docker which we need to understand: 

Concept 1 : Docker Hub: [central warehouse of container images] 

         Docker Hub is a cloud-based container registry provided by Docker Inc. 

         It allows users to store, manage, and distribute Docker images. It also allows to Upload images (docker push), Download images (docker pull), Share images with teams, Store private images securely

         It supports both public and private repositories and enables seamless image sharing across development, testing, and production environments.

         Just like: GitHub → stores source code and Docker Hub → stores Docker images

         Offical Website : https://hub.docker.com/


Docker Registery : 

          A Docker Registry is a centralized service that stores and distributes Docker images.
          
          It allows users to push, pull, and manage container images across different environments. 
          
          Docker Hub is a public registry, while organizations can host private registries for internal use. - Default One 

          Cloud based Other Registry - GCR [ Google Contatiner Registry ] and Amazon ECR 

          Local Registry : Nexus 3+, DTR [ Docker Trusted Registry ] 


Docker Images : 

         A Docker Image is a blueprint/template to create containers.
         
         Example: nginx image → used to run Nginx server container & mysql image → used to run MySQL database container

         These images are stored in Docker Hub.


Types of Repositories in Docker Hub

1. Public Repository

         Anyone can download and it is Free

         Example: nginx, redis, ubuntu

2. Private Repository

          Only authorized users can access

          Used in companies for internal apps


Important Terms in Docker Hub


               Repository	      Storage location for images

               Tag	      Version of image (e.g., nginx:1.25)

               Official Image    Verified & maintained by Docker

               Push       	      Upload image to Docker Hub

               Pull	      Download image from Docker Hub


Basic Docker Hub Workflow

Developer Side

                Build image:

                      docker build -t myapp .

                Login:

                      docker login

                Tag image:

                      docker tag myapp username/myapp:v1

                Push:

                       docker push username/myapp:v1



Concept 2 - Port Mapping 

               Port Mapping is the process of connecting a port on the host machine to a port inside a Docker container so that external users can access the application running inside the container.
               
               It is a Docker Engine runtime feature used when running containers.

               Port Mapping happens when you run a container using Docker locally.


Interview Definition: 

                Port mapping in Docker is a networking mechanism that binds a container’s internal port to a host machine’s port using the -p option in the docker run command, allowing external access to containerized applications.

Why Port Mapping is Required?

By default:

               Containers run in isolation.

               They are not accessible from outside.

               If your application runs inside container on:

               Container Port: 80

              It will NOT be accessible unless you expose it.

Syntax (Very Important)

         docker run -p <host_port>:<container_port> image_name
         
Example:

         docker run -p 8080:80 nginx

Meaning:

               Host Port → 8080

               Container Port → 80

               Now access: http://localhost:8080

               
How It Works Internally

              Container runs inside bridge network

              Docker creates NAT rule

              Traffic from host:8080

              Redirected to container:80

              It works using: Bridge network and iptables NAT rules


Without -p	

            App runs internally only	

            Not reachable from browser

            Fully isolated	

With -p

           App accessible outside

           Reachable via host port

           Exposed

           
Important Variations (Interview Points)

1. Expose Random Port

           Docker automatically assigns random host port.
   
           docker run -P nginx


2. Bind to Specific IP

          Only accessible locally.
 
          docker run -p 127.0.0.1:8080:80 nginx

3. Multiple Port Mapping
   
          docker run -p 8080:80 -p 3306:3306 myapp


Concept 3 - Container Data 

Basic Understanding :  When you run a Docker container, it contains:

                       Application files - Uploaded files

                       Configuration files - Modified settings

                       Logs - /var/log files

                       Database files - MySQL data

                       Temporary files - Cache files

All this information generated or stored inside a running container is called:

Container Data : 

             Container data is the data that is created, modified, or stored inside a running Docker container during its lifecycle.

             Container data refers to the runtime data generated and stored inside a Docker container, including application logs, configuration changes, temporary files, and database content. 
         
             By default, this data exists in the container’s writable layer and is lost when the container is removed unless external storage like volumes is used.

             Container data is:  Ephemeral (temporary) by default

                                 Stored in container writable layer

                                 Lost when container is removed

                                 Preserved using volumes or bind mounts


Where is Container Data Stored?

Docker containers are built using layers:

              Image layers (read-only)
              
              Container writable layer (read-write)

When container runs:

               New data goes into writable layer

               If container is deleted → writable layer is deleted

               That means data is lost.
