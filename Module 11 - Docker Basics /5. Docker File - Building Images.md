What is a Dockerfile?

             A Dockerfile is a text file that contains a set of instructions used to automatically build a Docker image.

             Instead of manually installing software inside a container, we write all steps in a Dockerfile.

             Interview Definition : A Dockerfile is a script containing a sequence of instructions that Docker uses to automatically build a Docker image in a reproducible and consistent manner.

             Definition 2 : A Dockerfile is a script containing instructions to build a Docker image automatically. 
             
                            It ensures consistency, automation, and reproducibility across environments by defining the base image, dependencies, configurations, and startup commands.


Why Dockerfile is Needed?

Without Dockerfile:

               Manual configuration 

               No standardization 

               No automation 

               Not reproducible 

With Dockerfile:

              Automated image creation 

              Same environment everywhere 

              Version control possible 

              CI/CD integration 

                        In DevOps, automation is everything — Dockerfile enables that.


How Dockerfile Works Internally

                Docker reads Dockerfile line by line

                Each instruction creates a new image layer

                Layers are cached

                Final output → Docker Image

Important Dockerfile Instructions (Must Know for Interview)

1. FROM

         Defines base image.

         FROM ubuntu:22.04

         its First instruction and Mandatory

2. RUN

          Executes command during image build.

                   RUN apt update && apt install -y nginx

          Creates new layer and Used to install packages
   

3. COPY

            Copies files from host to container.

            COPY app.py /app/
   
4. ADD

           Similar to COPY but supports:

                    URL download

                    Auto extract tar files

          ADD file.tar.gz /app/

Interview tip: COPY is preferred over ADD.


5. WORKDIR

                Sets working directory inside container.

                WORKDIR /app

   
6. ENV

               Sets environment variables.

               ENV APP_ENV=production
   
7. EXPOSE

               Documents which port container uses.

                   EXPOSE 8080

              It does NOT publish port — only documentation.

8. CMD

             Default command when container starts.

                 CMD ["nginx", "-g", "daemon off;"]

             Only one CMD allowed (last one takes effect).
   

10. ENTRYPOINT

            Defines main command that always runs.

                    ENTRYPOINT ["python"]

Difference: CMD → Default, can override  and ENTRYPOINT → Hard to override


10. USER

               Runs container as specific user.

                      USER appuser

               Security best practice.

11. VOLUME

              Creates mount point for persistent storage.

                      VOLUME /data

12. ARG

                Defines a variables that users can pass at build time

13. ONBUILD

                Adds to the image a trigger instruction to be executed at a later time

14. Labels

                Adds Metadata to an images 


Sample Dockerfile Example : 

                  FROM python:3.10
                  WORKDIR /app
                  COPY requirements.txt .
                  RUN pip install -r requirements.txt
                  COPY . .
                  EXPOSE 5000
                  CMD ["python", "app.py"]
