GIT TERMINOLOGY: 
----------------------

Git terminology means the important words and concepts used in Git to understand how it works

1.Working Tree (Working Directory)
   ---------------

- The working tree is the actual project folder where you create, edit, and delete files.

- The working tree is the current directory containing project files that a developer is actively working on.

 2.Repository (Repo)
   ---------------

- A repository in Git is a folder that contains the project files along with a hidden .git directory that stores the complete history of changes, commits, branches, and metadata. 
            
- It allows version tracking and collaboration.

Types: 

   1. Local Repository - Stored on your system
                             Created using: git init
                             
   2. Remote Repository - Stored on a server, Used for collaboration
                              Example platform: GitHub
                              Created by: git clone <url>
                              
   3. Bare repo → No working directory (used for sharing)
                      Example of bare repo: project.git
                      

3.Hash
   ---------------

- A hash in Git is a unique 40-character identifier generated using SHA-1 that represents file contents or commit data. 

- It ensures data integrity and helps Git track changes efficiently.
            
- Git uses:160-bit SHA-1 hash
            
- Why important - Detects file changes, Ensures data integrity, Identifies commits uniquely


4.Git Objects (Very Important)
-----

- Git stores everything as objects inside .git.

- Each object is uniquely identified using a SHA-1 hash.
                                  
- There are four types of objects:
                                           
   - Blob	     -  Stores file data
   - Tree	     -  Represents directory structure
   - Commit      -  Snapshot of project
   - Tag Named   -  reference to commit
                                           
5.Commit
   --------

- A commit is a snapshot of changes stored in the repository along with metadata such as author, timestamp, and message.

- Command: git commit -m "message"

         Each commit contains: Author,Timestamp, Commit message, Pointer to previous commit


6.Branch
   --------------

- A branch is a pointer to a sequence of commits.
            
- A branch in Git is a movable pointer to a commit, allowing developers to work independently and later merge changes.

HEAD 
-----

- HEAD is a special pointer that refers to the current branch.
      
- HEAD is a pointer that indicates the currently active branch and the latest commit on that branch.
      
- It tells Git where you are working.
      
- When you commit, HEAD moves forward.

Main / Master Branch - 
-----

- Default branch created when repository is initialized.
                      
- Usually named main (older repos may use master).
                       
- The main branch is the default branch in a repository and typically contains stable production-ready code.

7.Remote
   ---------------

- A remote is a reference to another Git repository (usually on a server).
            
- A remote is a connection to another repository, typically hosted on a server, used for collaboration and code sharing.
            
- Default remote name: origin
            
- Common commands: git push, git pull
            
- Popular remote hosting platforms: GitHub and GitLab

8.Commands, Subcommands & Option
   ------------------

- Git operations are performed using commands like git push, where push is a subcommand. Options such as --hard modify the command’s behavior.
- 
   Example: git push
  
               git → Command
               push → Subcommand
               Example with option: git reset --hard
                                    --hard → Option
