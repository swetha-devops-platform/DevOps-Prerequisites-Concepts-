INTRODUCTION: 
------------

What is Version Control System : 
----------------

- A Version Control System (VCS) is a tool that tracks changes made to files over time so that specific versions can be recalled later and multiple developers can collaborate efficiently.
          
- Another name for VCS is Software Configuration Management (SCM).
          
- It helps:

        - Multiple developers to work together
        - Tracking history of changes
        - Rolling back to previous versions
        - Managing branches (feature development)

Why Do We Need Version Control :
-----------------------

Without VCS: 

- Code overwriting happens
- No history tracking
- Difficult collaboration
- No rollback option
             
With VCS: 
             
- See what changes were made
- Know who made the changes
- Restore old versions
- Work with team members without conflicts
- Create branches for new features or bug fixes
- Tag versions (like v1.0, v2.0 releases)

TYPES OF VERSION CONTROL SYSTEM  :
-------------------------

There are 3 main types:

  - Local Version Control System
    
  - Centralized Version Control System (CVCS)
    
  - Distributed Version Control System (DVCS)

1. LOCAL VCS 
   -------
   
   - Definition : A Local VCS stores all file versions on the same local machine without any remote server.Local VCS maintains file versions on a single system and does not support team collaboration.
     
   - How it works: Stores versions on the same computer and No remote server
   - Example: Revision Control System (RCS)
     
   - Disadvantages: No collaboration
                     If system crashes → data lost

2. CENTRALIZED VCS 
   ---------
   
    - Definition : In CVCS, there is one central server that stores all versions, and developers connect to it to commit or update code.
                    Centralized VCS uses a single server to store code versions, and all developers depend on that server.
      
    - How it works: Single central server
                     Developers connect to server
                     All versions stored centrally
      
    - Examples: Apache Subversion (SVN) ,CVS
      
    - Advantages: Easy management
                   Simple structure
    - Disadvantages: If server fails → development stops
                      Requires internet connection
                      Slower compared to distributed

3. DISTRIBUTED VCS  (DVCS)
   --------------

   - Definition : In DVCS, every developer has a complete copy of the repository, including full history.
                     Distributed VCS allows each developer to maintain a full repository copy, enabling offline work and better reliability.
     
   - How it works: Every developer has full copy of repository
                      Can work offline
                      Push changes to remote server later
     
    - Examples: Git, Mercurial
    - 
    - Advantages: Faster
                    Works offline
                    More secure (multiple copies)
      
    - Disadvantages: Slightly complex for beginners

Difference between CVCS & DVCS : 
--------------------
- Repository -          In CVCS [Single central server], In DVCS[Each developer has full copy]
- 
- Internet Required     In CVCS [Yes], In DVCS[ No (for commits)
- 
- Speed	              In CVCS [Slower], In DVCS[Faster]
- 
- Server Failure        In CVCS [Stops development], In DVCS[No impact]
- 
- Backup	              In CVCS [Only server backup], In DVCS[ Multiple backups (each system)
- 
- Example	              In CVCS [ SVN ], In DVCS[ Git] 


In Interview Based : 

- In CVCS, code is stored on a central server and developers depend on it. 

- In DVCS, every developer has a complete repository copy, enabling offline work and better reliability.
